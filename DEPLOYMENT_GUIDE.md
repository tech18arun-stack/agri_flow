## 🌐 3. Server Setup (Ubuntu)

### Directory & Permissions
Ensure the target directory exists and the `www-data` (Nginx) user can access it:
```bash
# Create target
mkdir -p ~/My_Sites/agriflow

# Fix permissions for Nginx access
sudo chmod o+x /home/server
sudo chmod o+x /home/server/My_Sites
sudo chmod -R 755 /home/server/My_Sites/agriflow
```

### Nginx Configuration
The project includes a pre-configured `nginx_config`. To apply it on the server:
1.  **Copy to sites-available**: `sudo cp ~/My_Sites/agriflow/nginx_config /etc/nginx/sites-available/farmer_app`
2.  **Enable site**: `sudo ln -s /etc/nginx/sites-available/farmer_app /etc/nginx/sites-enabled/`
3.  **Restart**: `sudo systemctl restart nginx`

## ⚡ 5. Deployment Workflow

Whenever you make changes to the code, simply run:
```powershell
./deploy.ps1
```

**What this script does:**
1.  Runs `flutter build web` locally.
2.  Compresses and uploads build artifacts to the server via SCP.
3.  Uploads the latest `nginx_config` for easy server-side updates.

---

## 🛡️ 6. Appwrite API Proxy (Important)

To bypass CORS issues and secure your API, Nginx is configured as a **Unified Proxy**. 

### Nginx Logic:
*   `https://farmer.websitescorp.com` → Serves the **Flutter App**.
*   `https://farmer.websitescorp.com/v1` → Redirects internally to **Appwrite** (port 8080).

### Appwrite Console Step:
You **must** whitelist your domain in the Appwrite Console:
1.  Go to **Overview -> Integrations -> Platforms**.
2.  Add a **Web App** platform.
3.  Hostname: `farmer.websitescorp.com`.
